# سورس‌های محتوا

> زبان: **فارسی** | [English](../en/CONTENT_SOURCES.md)


## کانال‌های پیشنهادی انتشار

بهتر است از چند کانال استفاده کنی تا اگر یکی از مسیرها از دسترس خارج شد، کاربر هنوز راه دیگری برای گرفتن محتوا داشته باشد.

کانال‌های پیشنهادی:

- branch گیت‌هاب با نام `IR-packages`
- GitHub Releases
- mirror روی Git شخصی
- اطلاع‌رسانی در تلگرام
- Local Share بین کاربران
- انتقال با USB یا LAN

## داخل یک سورس محتوا چه باشد؟

ساختار پیشنهادی:

```text
packages.index.json
packages/
  package-name.azsos
```

registry قبل از دانلود به AZSOS متادیتا می‌دهد. اما خود فایل `.azsos` همچنان منبع اصلی برای verify است.

## نسخه‌گذاری بسته‌ها

از نسخه‌های واضح استفاده کن، مثل:

```text
0.1.0
2026.05.03
2026.05.03-1
```

هر وقت بسته‌ها تغییر کردند، registry را هم به‌روزرسانی کن.

## نظم سورس

- کلید خصوصی امضا را منتشر نکن.
- اسم بسته‌ها را پایدار نگه دار.
- بسته‌ها را کوچک و متمرکز بساز.
- تا حد امکان متادیتای منبع و تاریخ review را داخل بسته بگذار.
