# مدل امنیتی

> زبان: **فارسی** | [English](../en/SECURITY.md)


## ایده اصلی

AZSOS بین **کشف بسته** و **اعتماد به بسته** فرق می‌گذارد.

یک سورس فقط می‌تواند به AZSOS بگوید که بسته‌ای وجود دارد. اعتماد فقط بعد از verify رمزنگاری‌شده شروع می‌شود.

## بررسی‌های نصب

هنگام نصب بسته، AZSOS این موارد را بررسی می‌کند:

1. آرشیو قابل باز شدن باشد.
2. فایل‌های الزامی وجود داشته باشند.
3. هیچ مسیری از فولدر نصب خارج نشود.
4. `manifest.json` از `azsos.v1` استفاده کند.
5. همه فایل‌های لیست‌شده با `hashes.json` سازگار باشند.
6. امضای Ed25519 معتبر باشد.
7. اگر registry هش SHA-256 داده، با فایل دانلودشده یکی باشد.

## اعتماد به ناشر

AZSOS نام ناشر و fingerprint را نشان می‌دهد. کاربر می‌تواند fingerprint را فقط روی دستگاه خودش trusted کند.

این کار یک مرجع اعتماد جهانی نمی‌سازد؛ فقط یعنی: «من روی این دستگاه به این ناشر اعتماد دارم.»

## تهدیدهایی که AZSOS کم می‌کند

- دستکاری بسته‌ها
- دانلود ناقص یا خراب
- ZIP path traversal
- اشتباه گرفتن source با publisher قابل‌اعتماد
- جایگزینی بی‌صدای فایل بسته

## خارج از محدوده

AZSOS VPN، پیام‌رسان، آنتی‌ویروس یا ابزار ناشناس‌سازی نیست. ترافیک شبکه را مخفی نمی‌کند و تضمین نمی‌کند که هر source امن است.

## گزارش مشکل امنیتی

مشکلات امنیتی را تا حد امکان اول به‌صورت خصوصی گزارش کن. مراحل بازتولید، نسخه آسیب‌پذیر و اثر احتمالی را بنویس.
